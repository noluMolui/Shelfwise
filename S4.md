# S4: Product Management

## What was built

S4 supports the product Add, Edit, and View flows:

- Add and edit product name, SKU, category, description, unit price (ZAR), low-stock threshold, and supplier.
- Validate required fields and input limits; show duplicate-SKU and save errors without discarding entered values.
- Keep quantity out of the product form. Stock changes are intended to be recorded as stock movements.
- Make View mode read-only.
- Block saves while offline and return to the product catalogue after a successful save or cancellation.
- Use Supabase for product and supplier data, with a database migration defining the supporting schema, permissions, and row-level security.
- Match the signup screen's centered card layout, with the product heading, notices, and form grouped together.
- Keep production Add/Edit on the Supabase-backed `/products/new` and `/products/:id/edit` routes; only the `/preview/s4` route uses sample data and disables saving.

The app also includes a minimal product catalogue to support the S4 return flow.

## Previewing S4

Run the development server with `npm run dev`, then open:

`http://127.0.0.1:5173/preview/s4`

This development-only route opens the Add screen with sample values. It does not require Supabase and cannot save changes. The route is not enabled in production builds.

## Authentication and live data

The `/login` route signs in with Supabase Auth and returns users to the protected route they requested. The `/signup` route creates owner accounts. Product routes require an authenticated session and profile; Add and Edit are restricted to business owners.

Live CRUD requires a running Supabase project, the `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` values in `.env`, the database migration, and an authenticated account with a profile. The preview route is for inspecting the UI only and is excluded from production builds.
